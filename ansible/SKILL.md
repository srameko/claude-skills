## Structure

```
ansible.cfg                          ← inventory path, roles_path, no host key checking
inventories/production/
  hosts.yml                          ← single host: dns-server (ansible_user: ubuntu)
  host_vars/dns-server.yml           ← gitignored, generated by deploy.sh from 1Password
  host_vars/dns-server.op.yml        ← 1Password template (op inject source)
  host_vars/dns-server.yml.example   ← reference for required vars
playbooks/
  dns.sramkovi.family.yml            ← main playbook
roles/
  base/         ← apt update, packages, timezone
  hardening/    ← SSH, sysctl, admin users
  docker/       ← Docker installation
  nginx/        ← nginx + vhost templates
  acme_sh/      ← TLS certificates via acme.sh
  adguard_home/ ← AdGuard Home DNS
  fail2ban/     ← fail2ban + jail.local
  ufw/          ← firewall rules
scripts/
  deploy.sh     ← secrets injection from 1Password + playbook runner
```

## Secrets Workflow (1Password)

Secrets are **never stored in the repo** — always injected at deploy time:

```bash
# 1. Sign in to 1Password
eval $(op signin)

# 2. Run deploy script (injects secrets → runs playbook)
./scripts/deploy.sh

# Pass extra args through to ansible-playbook:
./scripts/deploy.sh --tags ssh --check
./scripts/deploy.sh --diff
```

`deploy.sh` runs `op inject` to populate `host_vars/dns-server.yml` from the
`.op.yml` template, then cleans up the file on exit via `trap`.

**Never run `ansible-playbook` directly** — always use `deploy.sh` to ensure
secrets are injected and cleaned up properly.

## Role Structure Convention

Each role follows standard Ansible layout:

```
roles/<name>/
  defaults/main.yml   ← all configurable variables with defaults
  tasks/main.yml      ← entry point, imports sub-task files with tags
  handlers/main.yml   ← service restarts etc.
  templates/          ← Jinja2 templates (.j2)
  meta/main.yml       ← role metadata
  molecule/default/   ← Molecule test scenario
```

Sub-task files are imported with tags:
```yaml
- name: SSH hardening
  import_tasks: ssh.yml
  tags: ssh
```

## Molecule Testing

Every role has a Molecule scenario using Docker + Ubuntu 22.04:

```bash
cd roles/<role-name>
molecule test          # full cycle: destroy → create → converge → idempotence → verify → destroy
molecule converge      # apply role only
molecule verify        # run verify.yml assertions
molecule destroy       # clean up
```

Test image: `geerlingguy/docker-ubuntu2204-ansible:latest` (pre-built, privileged)

**Idempotence is mandatory** — every role must pass idempotence check.

## GitHub Actions (Molecule CI)

Each role has its own workflow triggered on path changes:
```
.github/workflows/molecule-<role>.yml
```

Workflows use tag-based action pinning (not SHA) — **add SHA pinning when
updating or creating workflows** (see GitHub Actions security skill).

Steps: checkout → setup-python 3.11 → pip install ansible molecule → `molecule test`

---

## Adding a New Role

1. Create role structure: `ansible-galaxy role init roles/<name>`
2. Add defaults, tasks, handlers, templates
3. Add Molecule scenario (copy from existing role, adjust converge/verify)
4. Add GitHub Actions workflow (copy `molecule-base.yml`, update paths and role name)
5. Import role in the appropriate playbook
6. Test locally: `cd roles/<name> && molecule test`

## Common Tags

Run specific parts of the playbook:
```bash
./scripts/deploy.sh --tags ssh        # SSH hardening only
./scripts/deploy.sh --tags sysctl     # kernel hardening only
./scripts/deploy.sh --tags users      # admin users only
./scripts/deploy.sh --check           # dry run (all roles)
./scripts/deploy.sh --diff --check    # dry run with diff
```
